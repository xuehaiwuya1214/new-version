# 校园人像导拍

## 当前源码的摄影距离引导

模特先选定坐位、倚靠点或站位，并大致摆出参考姿态。摄影者依次完成 **粗对准中心 → 调整摄影距离 → 调倍率 → 复核中心 → 核对人物位置**，位置稳定后再提示模特微调局部动作。所有步骤支持显式跳过。

| 步骤 | 测量与提示 |
| --- | --- |
| 粗对准 | 参考中心在当前画幅中的投影进入短边 12% 内开始确认。 |
| 摄影距离 | 比较同一人体部位的实时／参考长度与远景特征点的实时／参考间距。两者相除，大于 1.14 提示摄影者后退，小于 1/1.14 提示前进，模特保持原位。连续测得比例合适才进入倍率阶段。 |
| 倍率 | 使用远景的尺度估计调节倍率。调整到设备边界时可显式跳过。 |
| 复核中心 | 倍率稳定后使用新帧复核中心，进入阈值为短边 8%。中心或景别明显偏离时回到对应步骤。 |
| 人物位置 | 浅金色细框标出参考人物，青色框角标出当前主角。仅在位置偏离时显示小中心标记。两张画面的双肩、双髋都清楚时比较四点的平均位置。任一侧躯干不可靠时，两侧都使用人物框中心。中心间距在画幅短边的 10% 以内持续 0.35 秒后进入姿势阶段。之后偏离超过短边的 15% 会重新核对位置。 |
| 局部姿势 | 把参考动作映射到当前主角的身体中心和尺度，比较关节和头肩角度，保留原有姿势提示时限。 |

系统优先使用匹配特征充足的参考塔楼。其他场景可在参考照片面板点击 **标记远景**，再点选主角远后方纹理清晰的建筑或固定景物。该选择假设远景确实在人物后方，单张照片无法确定两者的实际距离。若只有身旁的栏杆、台阶或背景过于模糊，请跳过摄影距离。缺失可靠人体或地标测量时系统暂停前后移动提示。多次测量显示移动没有带来改善时会提示停下检查。

更新电脑导拍服务，并重建手机端才能启用完整流程。新版页面创建会话时发送 `workflow=composition`，可用 `farX`、`farY` 指定参考画幅内的归一化远景坐标。返回的 `checks` 顺序为 `background, distance, framing, recenter, position, pose`，`distance.ratio` 是人景相对比例。人物位置依据由 `position.basis` 返回，取值为 `torso` 或 `box`。旧客户端沿用四步协议。以下带版本号的说明和旧评测记录描述相应历史版本。

验证命令：`python -m pytest -q tests/test_composition.py`。浏览器端到端回放使用 `python tests/composition_flow.py 参考照片路径`，建议使用正式图库中的圆塔样本 `REF_046.webp`。

## Android 安装包：小米 HyperOS

Android 10 及以上可安装 APK，直接从桌面打开。1.2.1 的构建输出为 **`build/apk/campus-photo-guide-1.2.1.apk`**，沿用「校园人像导拍」及包名 `cn.campus.photoguide`。这是本地产物，尚未上传 GitHub Release。分享给队友时发送这个 APK 文件，GitHub 的源码 ZIP 不能直接安装到手机。

**当前 APK 是连接电脑的轻量客户端：手机负责原生相机取景、拍摄、显示引导和保存照片；参考图识别、背景匹配、人物与姿势检测、图库检索都在电脑运行。** APK 不包含模型。当前默认使用「实时识别」，AI 导拍需连接电脑，直接拍照无需连接。「录制演示」保留为手动模式，不持续送检，不能用于证明实时识别性能。下面的 PWA 是另外保留的离线网页版本，两种运行方式不同。

**1.2.1 对齐与变焦转场。** 中心对齐后，显示短暂光晕、彩色点阵及渐变细边框；实际开始自动变焦时，光框向屏幕边缘展开，倍率按钮同步亮起，随后淡出。参考背景轮廓仍固定在目标构图上。动画不决定是否对齐，也不提前进入站位阶段，最终仍等待新画面复核。只复用上一张识别小图；不额外取帧，不对实时相机画面做模糊，动画仅改变叠加层的位置、缩放和透明度。暂停、跳过、手动变焦及换图会清理动画；系统开启减少动态效果时改为短暂淡入淡出。

可运行 `python tests/framing_effect_flow.py --scene 校园照片路径` 生成界面预览与回归报告（需要 Playwright、Chromium 和 Playwright 的 ffmpeg 组件）。输出在 `build/qa/framing-effects`，录制使用模拟相机及匹配结果，仅展示实际界面动画，不代表手机帧率或模型识别效果。

1. **安装。** 把 APK 传到手机，用「文件管理」打开。若系统提示来源未授权，只给这次使用的文件管理器开启「允许安装此来源的应用」，按系统提示完成安装。
2. **启动电脑服务。** 电脑按下方说明准备好 Python 环境和模型后，双击 `start-phone.cmd`，保留启动窗口。窗口会打印 `http://电脑IP:7862`。让手机与电脑连接同一 Wi-Fi；外拍时也可以打开手机热点，让电脑连到该热点。
3. **连接与选图。** 打开 APP，在左上角设置里的电脑服务连接栏填写刚才的地址并连接，例如 `http://192.168.1.20:7862`。使用实际地址，不要填写 `localhost`、`127.0.0.1` 或 `0.0.0.0`。然后从电脑图库选参考图，或点「打开照片」选择手机相册里的原图。首次分析需要等待电脑加载模型。
4. **拍摄。** 打开后允许相机权限即可取景。1.2.0 使用 CameraX 原生预览，默认清晰优先；设置中的预览质量不限制正式照片的尺寸。实时识别最多每秒发送一张小图给电脑，每步都可跳过。需要手动演示时再切换到「录制演示」。点按取景画面可以对焦，点击快门独立拍摄高分辨率照片。
5. **保存与分享。** 拍后界面显示原图的实际宽、高和文件大小，点「保存原图到相册」，照片写入手机 `Pictures/CampusPhotoGuide`。点「分享照片」调起系统分享面板。两者使用同一份原生 JPEG 文件，不含辅助线，也不把界面的缩略预览当成成片。

连接失败时，先核对电脑当前 Wi-Fi/热点的 IPv4 地址；电脑有虚拟网卡时可能显示多个地址。若 Windows 防火墙弹出询问，可按需允许 Python 在**专用网络**通信。校园 Wi-Fi 可能隔离设备，此时可改用手机热点；不用把电脑的 `8001` 端口单独开放给手机。`start-phone.cmd` 监听 `0.0.0.0:7862`，原有 `start.cmd` 仍默认使用 `127.0.0.1:7861`。

若相机被拒绝，在系统「设置 → 应用 → 校园人像导拍 → 权限」中允许相机，再回到应用重试。Android 10 及以上通过系统相册接口保存本应用照片，不需要授予整个存储空间的管理权限。


**1.2.0 原生预览与独立拍照。** Android 使用 CameraX 1.6.2，同时绑定 `Preview`、`ImageAnalysis`、`ImageCapture`。预览直接显示在透明 WebView 下方的原生 `PreviewView`，网页保留按钮和引导线，不读取视频像素来刷新预览。CameraX 的分析缓冲区只在网页明确请求小图时转换为 JPEG（长边最多 640、质量 75）；其余帧立即释放，只有一张样本在途。拍照使用独立 `ImageCapture`，在设备支持的普通静态输出尺寸中优先选高分辨率，质量 95。不会把识别用的 640 小图保存为成片，也不会在原生拍照失败时悄悄回退到预览截帧。

三个用途通过同一 `ViewPort` 对齐裁切区域，保持取景、识别和成片构图一致；识别样本处理传感器旋转及前置镜像。倍率通过 CameraX 相机控制调整，不再叠加网页数字裁切。原图留在手机应用缓存中，网页只收到照片编号、尺寸及小预览，保存/分享时直接复制原始 JPEG，避免大图 Base64 跨网页传输。预览档位不再决定照片分辨率。实际成片尺寸仍取决于设备输出能力、同时使用的相机通道和全屏构图裁切，不能保证达到传感器标称最大像素，也不能保证具有小米系统相机全部的计算摄影处理。

验证清晰度时，可先选择「先只拍照」，不连接电脑，拍摄后点击「保存原图到相册」，在系统相册的详情中查看尺寸；对比时使用原文件，避免微信缩图影响判断。`python tests/native_capture_flow.py` 验证不打开 WebView 相机、不截预览帧、原图编号保存/分享、小图检索、暂停识别、变焦、切镜头和失败处理。它模拟原生硬件边界；真实对焦、图像细节、原生预览流畅度及 MediaStore 仍需手机验证。API 依据：[CameraX 用途组合](https://developer.android.com/media/camera/camerax/architecture)、[独立拍照](https://developer.android.com/media/camera/camerax/take-photo)。

**1.1.0 手机相机界面。** Android APP 打开即启动全屏取景，白色快门和可拖动的倍率环固定在底部。点倍率环可展开精确滑杆。左上角「设置」包含电脑连接、预览质量、暂停识别和调试数据；右上角可以查看或导入参考图。

**1.1.1 电脑连接弹窗。** 取景页顶部可直接查看电脑连接状态并修改地址。未连接时点击风格推荐，会先打开连接弹窗，展示启动电脑服务、连接同一网络和填写地址三个步骤；连接成功后继续本次检索。失败时保留输入供重试；「先只拍照」可返回相机，取消本次待执行的检索。已保存的地址在下次打开时尝试重连；网络错误只更新状态，不反复弹窗打断取景。

在底部输入风格，点击箭头（或点风格标签）。APP 只为这次检索采集一张长边 640 像素的当前画面，携带风格文字送到电脑，不持续发送检索截图。电脑以 SigLIP2 的图像和文本向量筛选相关候选，再按缓存的 NIMA 美学分降序取最多 5 张，并剔除近重复图；相关候选不足时展示实际数量。卡片可左右滑动、居中选择，点击「就拍这张」才下载原图并准备导拍。

手机参考图按当前取景器画幅裁切，优先保留检测到的主角；参考预览、轮廓坐标、送检帧和最终照片使用相同画幅。开启全屏前不需要上传参考图，也可以直接按快门拍摄。选图之后按对准、景别、站位、姿势推进，底部固定显示简短提示。每条提示至少显示 3 秒，新提示只保留最新一条，阶段切换也遵守这个时长。

姿势环节最多进行 5 轮、每轮至少 3 秒的前台提示；同一建议可以稳定保留。暂停识别或切到后台不消耗轮次。提前识别对齐即可拍摄；5 轮结束后，即使仍未对齐也提示「可以拍摄了」并开放快门，停止连续送检。这是产品允许的宽松拍摄出口，记录为 `pose_budget`，不代表模型判定所有姿势达标。换图或重新开始会清空轮次。

**升级需同时重启电脑服务并安装新 APK。** 运行 `start-phone.cmd` 会用成员 2 的虚拟环境启动本仓库的 `scene_recommend.py`，内部接口为 `127.0.0.1:8001`，复用成员 2 的模型与图库缓存，无需修改其源码。手机仍连接 `http://电脑IP:7862`。若自行设置 `PHOTO_RECOMMEND_URL`，目标服务须支持 `/recommend-scene` 的 `scene_image` 字段和最多 5 张结果。旧的 8000 推荐服务不支持新协议。

验证命令：导拍环境运行 `python -m pytest -q tests/test_library.py tests/test_phone_frame.py`、`python tests/phone_ui_flow.py`；推荐环境在 `PYTHONPATH` 包含成员 2 目录时运行 `python -m pytest -q tests/test_scene_recommend.py`。页面测试使用模拟相机与服务器，不能替代真机性能测试。

**1.0.5 实时定锚与镜头变焦。** 本版基于 `sfeyi/new-version` 的 `fix/android-camera-preview`（`39a8e80`），保留其 VideoFrame 与 Worker 取帧优化。第一次可信背景匹配确定参考中心的落点，同时保存取样时的手机方向；电脑响应回来后按最新方向投影，避免网络延迟造成白点追赶旧画面。之后的匹配继续核验是否对齐，但不重新定位白点。Android 优先使用原生相对旋转传感器（`TYPE_GAME_ROTATION_VECTOR`），只传输约 30 次/秒的小型方向矩阵；不读取相机像素。设备不提供该传感器时依次使用旋转向量、网页方向事件，完全没有方向数据时使用原有视觉跟踪。进入景别或暂停时停止方向监听。

该方向跟随只近似补偿转动，视场角采用估计值，不能补偿走动平移、遮挡或长期漂移；变化较大时使用「重新对准」。白点短暂失去视觉匹配后会变淡并继续跟随方向，不能凭旧落点自动过关；阶段确认仍使用电脑返回的新几何结果。

中心确认后，参考背景的完整轮廓固定显示，复用刚才送检的小图播放约 1 秒的毛玻璃过渡（不对实时视频持续做模糊、不额外截帧）。利用已测量的景物尺度估计倍率，过渡结束后开始变焦。摄像头暴露 `zoom` 能力时使用 `MediaStreamTrack.applyConstraints` 调整实际视频流，范围取设备能力、最高限制 8×；界面显示「镜头变焦」。不支持或拒绝控制时显示「画面放大」，回退为有限的数字裁切。设备 zoom 不保证为光学变焦或切换物理镜头。等待设备命令完成并稳定后再取新帧核验景别，随后自动进入人物站位和姿势；硬件已放大的视频不会再重复裁切一次。手动拖动倍率、暂停、换图或切换镜头会取消尚未执行的自动计划。

本版不改变电脑接口，但修改了手机页面和方向插件，必须重新构建、安装 APK。`python tests/motion_zoom_flow.py` 验证定锚、延迟补偿、镜头控制/回退、过渡和站位/姿势衔接；这些模拟硬件测试不能代替小米实机变焦与方向跟随测试。

开启相机时按浏览器能力请求 `zoom: true`，避免未请求变焦访问导致可用倍率范围被隐藏；实际能力仍以设备返回结果为准。接口依据：[MediaStream Image Capture](https://www.w3.org/TR/image-capture/#dom-mediatrackcapabilities-zoom)。

**1.0.3 录制演示模式。** 为优先保证录屏取景，演示模式关闭自动截帧、编码、传图与实时匹配，只在用户按快门时读取一次相机画面保存照片。白点使用手机方向数据做近似投影，以独立页面元素移动，不因识别超时消失；方向数据不可用时仍可点按放置白点并手动确认。此方法不能跟踪平移、遮挡或真实地标，不能作为识别准确率演示。界面始终标注「演示 · 手动确认」。

演示中白点接近白环、保持约 0.65 秒会进入景别，也可手动确认。随后显示参考轮廓，并在开启「演示变焦」时播放一次 1.12× 的预设倍率变化（上限取当前变焦能力；纯数字裁切为 1.6×），这不是测得的建筑匹配倍率。站位框与动作轮廓来自参考图，用户分别点「站位已合适」「动作已摆好」进入拍摄；不生成虚假的实时人物检测结果。切换模式会重新开启相机，以释放旧取帧资源。参考准备完成后可以断开电脑继续本轮演示；换参考图仍需电脑。手机真机的持续录屏表现仍需验证。

**实时识别的预览优化。** 对准和景别阶段不再持续重绘没有变化的白环与轮廓；只有新结果、白点移动/消失或短暂特效时才更新。Android 辅助线动画最多约 15 帧/秒，辅助线画布采用较低像素密度，不改变相机或照片分辨率。连接请求失败后自动暂停送帧与引导，重新连接电脑后可恢复；物理断网到发现失败之间仍可能等待网络超时。

「显示辅助线」可以独立关闭绘制而继续识别，「暂停识别」会同时停掉送帧与绘制。排查时保持相同场景，比较正常导拍、只关闭辅助线和暂停识别的预览读数：只关闭辅助线即改善，说明叠层负担较大；仍卡但暂停后改善，继续检查截帧、编码与桥接。断开电脑不会立即停掉旧版手机的本地操作，不能单独据此判断是网络还是相机故障。

1.1.1 及以前的手机版本默认请求 720p、30 帧/秒的 WebView 视频预览，取帧编码可使用 Worker。1.2.0 已改用上面的原生通道，诊断信息标注 `camerax` / `native-camerax`；不再把网页视频计数器的零帧率误报成原生预览帧率。两种路径都限制实时识别最多每秒一次、长边 640、JPEG 质量 75，且只有一帧在途；超过 3.5 秒的普通识别结果不再授权快门。新原生快门使用最近有效的引导状态，直接调用独立拍照，不等待电脑回传照片。

本地取帧优化：支持 `VideoFrame` 的 WebView 会先转移视频帧，再在 Worker 内完成裁切、缩放、JPEG 编码和 Base64 转换；相机帧在编码前释放。不支持或拒绝该路径时回退到 `ImageBitmap`，再不可用时使用小画布。旧实现的 `createImageBitmap(video, …resizeOptions)` 在页面线程发起裁切缩图，不能因为后续 JPEG 在 Worker 中就认定取帧没有界面开销。该优化减少页面线程上的图像处理，但仍共享设备 GPU/内存资源，不能承诺所有手机不掉帧。[Chrome 的视频帧与 Worker 说明](https://developer.chrome.com/docs/web-platform/best-practices/webcodecs)。

Android 取景时可展开「卡顿排查数据」，查看实际视频尺寸、设备报告的帧率、最近一次手机图片准备耗时、请求往返、电脑处理耗时和图片大小；`video-frame` 表示新处理路径，`image-bitmap` 和 `canvas` 表示兼容回退。新增「低负载 · 480p」供对照测试，会降低预览及保存照片的分辨率。识别结果按采样时间计算有效期：即使下一请求仍在等待，旧结果超过 3.5 秒也会撤回可拍摄状态。

本地回归：`python tests/frame_pipeline_flow.py --executable "浏览器可执行文件路径"`。测试使用模拟相机和模拟原生网络接口，真实运行视频帧转移、Worker 和 JPEG，验证裁切/变焦、回退、取消、单帧在途，以及 6 秒慢响应期间预览继续和旧快门资格失效。它不测试 Android 原生桥接性能、真实相机、模型耗时或局域网延迟。修改手机静态资源后必须重新构建并安装 APK；只重启电脑服务不会更新手机里打包的页面。

手机选图时，最多 5 张卡片逐张加载电脑生成的 320 像素缩略图；进入导拍后暂停图库图片加载，选作参考时仍读取原图。设置中的「暂停识别」可关闭送帧和辅助线，直接观察纯预览；再点「继续识别」恢复。原生相机的预览档位仅影响取景，正式照片使用独立拍照尺寸。普通浏览器及旧版 APK 仍从预览截帧，其照片分辨率受视频流、画幅裁切及数字放大限制。

1.0.5 的手机优化不改变电脑接口，现有兼容服务可以继续使用。覆盖升级正式应用需要沿用原签名密钥；此前独立安装的「校园导拍·优化测试」使用不同包名，不会被正式版覆盖。若电脑还运行 1.0.0 时的服务，请关闭旧服务窗口后重新运行 `start-phone.cmd`，使缩略图接口和慢采样判定生效。排查时可在开发工具查看 `window.__guidePerformance`：`mode` 区分 `demo` 与 `live`；`prepareMs` 是手机截帧/图片准备耗时，`requestMs` 是请求往返耗时，`serverMs` 是电脑解码、排队和推理耗时；两者之差还包含桥接和序列化，不能直接视为纯网络延迟。`overlayPaints`、`overlayMs`、`longTaskMs` 分别记录最近一次统计间隔内的绘制次数、绘制调用耗时、界面长任务耗时。浏览器回归验证不替代小米真机帧率测试。

这个版本用 Capacitor 承载 Android 控件页面，CameraX 负责相机，并接入原生网络请求、相册保存和分享。局域网通过原生 HTTP 请求访问电脑，无需给电脑配置 HTTPS；APP 页面仍保留本地安全来源。当前没有完成小米真机验证；摄像头权限、原生预览、照片保存和现场识别速度需在实际手机上测试。

## 推荐选图与四步导拍

### 在新电脑准备推荐服务

两个仓库与共享图库放在同一父目录，导拍与推荐各用自己的虚拟环境。推荐依赖单独安装；不必把队友的整个环境覆盖到导拍环境上。下面以 Windows、Python 3.13 和 CPU 为例，特征缓存只需首次生成或更新图库后重建。


导出脚本保留已有的正式标签，按照片编号复制原图。如果输入仅有 `sources.json`，未经确认的人数、姿势等字段保留 `null`。已有可用的 CUDA 环境可使用队友仓库的 CUDA 安装命令，并改用 `--device cuda`。

## 手机网页实地测试（PWA）

**[手机打开校园人像导拍](https://xuehaiwuya1214.github.io/new-version/)**。把这个链接发给队友即可。手机用可安装的网页应用（PWA），第一次联网下载约 **128 MB**。识别和拍摄都在手机上完成，可以独立带到校园使用。GitHub 的「Code → Download ZIP」是供电脑开发使用的源码。

1. **添加到主屏幕。** Android 用 Chrome 打开上面的链接，点右上角菜单 →「添加到主屏幕」或「安装应用」→「安装」。iPhone 用 Safari 打开链接，点「分享」→「添加到主屏幕」→「添加」。如果有「作为网页 App 打开」，请开启。收到微信群链接时，可先用「在浏览器打开」切到 Chrome 或 Safari。也可以直接在浏览器标签页测试。[Android 操作说明](https://support.google.com/chrome/answer/9658361?hl=zh-Hans&co=GENIE.Platform%3DAndroid) · [iPhone 操作说明](https://support.apple.com/zh-cn/guide/iphone/iphea86e5236/ios)
2. **出发前下载。** 从准备外拍时使用的桌面图标或浏览器打开应用，连 Wi-Fi 点「下载离线包」，保持页面打开，直到顶部显示「离线包已就绪 · 可断网取景」。下载中断可点「继续下载」。可以打开飞行模式，关闭后从同一图标重新进入，确认仍显示「已就绪」。清理浏览器数据、切换浏览器或重装后，需要重新下载。
3. **准备参考照。** 先把选好的校园人像原图存到手机相册或「文件」，保证离线也能打开。点「打开照片」选择 JPG、PNG 或 WebP，等待识别主角和地标。首次启动引擎和分析参考照可能需要一会儿。队友已有的参考图库可直接使用，公开仓库只附原图指纹和机位文字。也可以选自己拍的人像。
4. **取景。** 点「开启相机」，允许摄像头权限，默认使用后摄。到参考地点先把白点移入白环，再对照建筑轮廓调整景别，随后按红色站位框和白色动作轮廓调整人物。四个环节都可跳过。室内可把同一张校园人像同时选作参考照和「用照片试拍」，观察是否依次通过。
5. **保存到手机。** 当快门亮起，点「拍摄并保存」。核验成功后，取景器下方会出现本次照片。点「保存到相册或分享」选择系统的保存选项，或点「下载 JPEG」到下载目录。在 iPhone 上也可长按这张照片保存。保存的是干净原片。参考照和取景画面只在本机处理。

**常见情况**

- **开启相机被拒绝。** 在浏览器的网站权限和系统的浏览器相机权限中允许摄像头，回到上面的 HTTPS 链接重试。浏览器内的「用照片试拍」也能走完整引导。
- **导入相册照片失败。** 如果原图是 HEIC，而文件选择器没有提供兼容照片，请先导出为 JPEG。参考照限 24 MB、4500 万像素。
- **背景一直未对上。** 确认能看到参考中的同一段建筑边缘或固定景物。室内测试或遮挡较多时，可依次点「跳过对准」「跳过景别」，直接测试人物。现场反馈请记下手机型号、浏览器、参考照编号以及卡住的步骤。

## 手机网页版本如何发布

推送到 `main` 后，GitHub Actions 从 `mobile/build.py` 构建静态页面并部署到 GitHub Pages。新仓库首次部署时，在 Settings → Pages → Build and deployment 中将 Source 设为 GitHub Actions。页面、模型与运行库均来自同一站点，离线下载会核对每个文件的 SHA-256。应用更新在关闭旧页面后生效。

手机后台 Worker 用 Pyodide 运行与桌面共用的取景逻辑和 OpenCV，用 ONNX Runtime Web 的单线程 WebAssembly 执行五个模型。后台只分析一帧，完成后再采下一帧，预览和按钮继续响应。机位、站位、姿势的判定阈值与桌面相同。实际识别速度取决于设备、参考图里的人物大小和背景特征。[Pyodide](https://pyodide.org/) · [ONNX Runtime Web](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html)

本地构建手机站点需要 Python 3.11 或以上。首次构建下载固定版本的运行库，之后可用本地缓存重复构建。在项目根目录运行以下命令，再在电脑浏览器打开 `http://127.0.0.1:8080/`。手机实测使用上方 HTTPS 入口。

```sh
python mobile/build.py
python -m http.server 8080 --bind 127.0.0.1 --directory build/mobile
```

## 实时识别模式：拍摄时怎么跟

| 阶段 | 取景器里的操作 | 判定依据 |
| --- | --- | --- |
| 对准 | 首次找到参考背景后，白点锁在同一处景物上，白色小环固定在画幅中心。Android 用手机相对旋转投影白点；没有方向数据的网页沿用视觉光流跟踪。电脑继续核验实际背景。 | 中心误差进入画幅短边的 8% 后开始确认，确认期间超过 10% 才退出；连续确认 0.32 秒进入景别。通过后记为完成，不因移动、失配、变焦或短暂暂停重新要求对准。 |
| 景别 | 参考背景完整轮廓立即出现，约 0.9 秒逐渐亮起，同时播放约 1 秒毛玻璃过渡，随后轻扫 0.45 秒。有可靠倍率建议后，用约 0.85 秒平滑变焦，优先调用相机 zoom，能力不足时使用有限数字裁切。轮廓固定，镜头画面缩放；拖动滑杆可随时接管。 | 动画和设备变焦期间暂停识别，结束后用新画面核对背景地标间距，达到参考的约 89%～113% 并保持 0.32 秒后通过；后续允许约 85%～118%。大小已经接近时不强行放大，也不重复核对中心。 |
| 站位 | 红色矩形表示参考人物的位置和大小，青色框角表示当前主角。按提示让模特大致站进目标框。 | 两个人物框的交集占并集至少 45%，持续 0.35 秒即通过。调整姿势时允许降到 35%，便于抬手、迈步。 |
| 姿势 | 白线勾出参考主角的头、身体和四肢，固定在取景画面上。模特照着轮廓摆动作，青点跟踪真人，箭头指向当前最需要靠近的参考关节。 | 逐帧比较同一画幅中对应关节的位置及头肩倾角。用参考人物尺度给关节留出容差，保持 0.50 秒即通过。半身照只考核参考中可靠的部位。 |
| 拍摄 | 出现「可以拍摄」后点「拍摄并保存」。 | 快门会用按下时的画面再核验保留的步骤，然后保存同一帧的干净 JPEG。 |

对准、景别、站位和姿势的提示旁都有「跳过」按钮，选择在本轮保留。背景一直匹配不上时，依次跳过对准和景别即可直接安排人物。四步都跳过可手动拍摄。点「恢复全部步骤」或打开新参考照会重新开始自动引导。

景别步骤支持钟楼、圆塔、灯塔及语义清晰的建筑、桥梁。SegFormer 先确定建筑区域，塔楼沿用天际线和钟面提取，其他建筑提取可见外沿；长线段提供屋檐、墙边等结构细节。人物遮挡和画幅裁切边缘不绘成建筑线。仅有钟楼地点名而实际只看见栏杆时不生成塔楼轮廓。轮廓始终使用参考画幅坐标，不跟随实时建筑移动。

其他背景结构也会生成较淡的稀疏长轮廓：在载入参考图时提取一次，去掉人物和画幅边缘，最多保留 35 条路径。没有可辨认轮廓时仍使用固定地标。手机 PWA 与电脑共用轮廓显现、轻扫和平滑变焦代码，离线包包含全部依赖。变焦期间预览与取景裁切同步变化，结束后重新识别才可通过；手动倍率、关闭自动匹配、跳过、更换图源或切到后台均会中止旧动画。

电脑背景核验采用固定关键帧的双向光流跟踪，排除人物区域，核对分散的角点与几何一致性；静止时忽略亚像素噪声。Android 的白点在首次匹配后使用手机方向投影，不跟随每次核验结果跳动；短暂失配时保留并降低亮度，但不能据此自动通过。没有方向数据时沿用视觉白点，失配后淡出、重新取得连续定位证据后显示。两种方式都不提前将白点吸到屏幕中心。

确认中心后播放约 1.6 秒的金色亮环，取景器顶部同时显示“中心已锁定”和当前下一步。对准只做一次，后续不自动返回第一步；点“重新对准”、更换参考照/相机来源或“恢复全部步骤”才重新开始。提示至少保留 3 秒，新方向持续 650 毫秒才进入替换候选；阶段变化和操作反馈也遵守最短展示时长。

白点表示**参考画面中心在当前镜头中的投影**，不是建筑包围框的中心；否则会改变原参考的人像构图。主体建筑有足够特征时，背景匹配还要求建筑区域内存在匹配证据。白点落在画外时用白色箭头指向它所在的一侧。景别阶段若没有清晰建筑，则用最多四个固定地标核对位置与间距。

机位接近并稳住后，系统比较多对地标间距，按比例调整倍率，再采一帧核对景别。支持相机 zoom 时采用设备范围（最高 8×），否则使用 1.0～1.6× 的数字裁切。例如，同一段屋檐在镜头里只有参考图的七成宽，倍率会从 1× 调到约 1.43×。到达倍率边界仍有偏差时，相机会提示靠近或后退。近处和远处的地标间距变化不一致时，会提示调整拍摄位置。照片试拍、相机预览、人物引导和保存的 JPEG 共用同一套取景裁切。

动作轮廓来自用户选中的参考人物。人物分割可靠时，白线沿真实外缘描画，也保留弯臂形成的空隙和部分内部线条。分割细节不足时，根据可见关节绘制简化动作轮廓，取景器图例会标出这一点。拍摄的 JPEG 只包含原始取景画面。[鹿酱的取景演示](https://www.douyin.com/video/7641535087246702202) · [华为导入参考姿势的说明](https://consumer.huawei.com/cn/support/content/zh-cn16094218/)

室内书架和窗框也可以充当地标。近景会用 PP-HumanSeg 保留头肩两侧的真实背景。如果连续两帧的背景证据都明显支持相反的左右方向，页面会自动水平翻转参考预览，重新提取同一主角的目标姿势。参考照下方可以手动翻转或还原。拍摄结果沿用相机方向。

## 人体识别和实现

- `people.py` 用 YOLOX-Tiny HumanArt 先找人，再把主角裁成 192 × 256 的输入交给 RTMPose-m Body7，解码 17 个 COCO 关节。全图没有清晰主角时会放大局部重检。参考照常规方向无法建模时会尝试旋转，并把结果映回原图。路人进入画面时优先跟踪已选的人。[RTMPose 官方项目](https://github.com/open-mmlab/mmpose/tree/main/projects/rtmpose) · [rtmlib 的检测与姿态流程](https://github.com/Tau-J/rtmlib/blob/main/rtmlib/tools/solution/body.py)
- `outline.py` 用 PP-HumanSeg 分割参考照中选定的主角，将轮廓映射到原图坐标。每张参考照只提取一次，翻转参考照或重新点选主角时重新提取。`posture.py` 比较站位框和固定关节。参考点置信度阈值为 0.52，实时点为 0.36，参考中可靠的关节在当前帧消失时会提示露出该部位。
- `background.py` 先在人物以外比对 RootSIFT 特征，传统匹配找到的对应点不足时，再用 XFeat 和 MAGSAC 寻找同一地标。XFeat 的结果至少需有 24 个不同位置的内点，并在两幅图中都有足够分布。`landmarks.py` 用多对相隔较远的背景点测量相对倍率。`guide.py` 负责稳定判定、阶段推进和回退。[OpenCV 特征匹配与单应变换](https://docs.opencv.org/4.x/d1/de0/tutorial_py_feature_homography.html) · [XFeat 官方实现](https://github.com/verlab/accelerated_features)
- `building.py` 在载入参考照时使用量化的 SegFormer-B0 分割天空、建筑、钟面与人物。它筛选两侧有天空、比例和高度合适的塔身，在原图上用 GrabCut 细化轮廓。钟楼近景可单独提取钟面及相邻墙边。轮廓使用参考画幅的归一化坐标，翻转参考照时会从翻转后的画面重新生成。[SegFormer 模型说明与许可](https://huggingface.co/nvidia/segformer-b0-finetuned-ade-512-512)

先对圆心、稳住手机再变焦的交互参考了华为的辅助构图说明。本项目用上传的参考照提供构图目标。单帧相对深度能描述景物的远近，复拍还需要确认两张图里具体哪几处是同一地标，因此当前使用跨图匹配测量倍率。[华为操作说明](https://consumer.huawei.com/cn/support/content/zh-cn16073539/) · [Depth Anything V2](https://github.com/DepthAnything/Depth-Anything-V2)

人体检测与姿态权重取自 OpenMMLab，人像分割权重取自 OpenCV Zoo，XFeat 使用 V1.0.0 的稀疏 ONNX 导出，SegFormer 使用 ADE20K 的 B0 量化导出。模型都在本机使用 ONNX Runtime CPU 推理，文件可用 PowerShell 的 `Get-FileHash models/*.onnx` 核对。SegFormer 权重适用 NVIDIA 的非商业研究或评估许可，原文随模型提供。

## 对接上游

1. `GET /api/library` 返回目录、地点及按照片编号访问的 `image_url`。`POST /api/recommend` 接收成员 2 原有查询字段，代理到 `/recommend`，补充可加载的图片地址与机位说明；原始照片通过 `GET /api/library/<photo_id>/image` 读取。
2. `POST /api/session` 以 multipart 传入 `reference`。可附 `viewpoint`、归一化主角坐标 `x/y` 和 `mirror=1`。返回 `id/reference`，`aimPoint=[0.5,0.5]` 表示参考画幅中心；`centerTolerance` 是允许的中心距离占短边的比例；人物框、关节和轮廓都在固定参考坐标中。手机与桌面都会保留检索选图带入的机位说明。
3. `POST /api/session/<id>/frame?seq=1` 发送同画幅 JPEG，帧号递增。四个引导阶段为 `background`（对准）、`framing`（景别）、`position`（站位）、`pose`（姿势），完成为 `ready`。`skip=background,framing` 可跳过整个背景环节；省略沿用，`skip=` 恢复全部。`completed` 中的 `background` 表示中心已经确认，后续不自动撤销；重新对准时递增 `source`。`checks` 按上述四步排列，跳过项为 `null`；`background.centerOk/scaleOk` 分别表示中心与景别判断。旧版只有三个检查项，接入方需要同步更新。
4. `DELETE /api/session/<id>` 释放会话。手机浏览器需要 HTTPS 或 localhost 才能使用摄像头。安卓电脑调试可用 `adb reverse tcp:7861 tcp:7861`。

`buildingOutline` 为 `{name, kind, paths, details, bounds}` 或 `null`，外沿、结构线和边界框均是固定参考坐标。稳定后 `zoomFactor` 建议乘到当前倍率，**仅在景别步骤**应用；客户端须重新采样验证。切换来源时更新整数 `source`，重新累计稳定时间。白环大小只是视觉标记，自动通过依据实际中心距离阈值。

`backgroundOutline` 为 `{kind:"background", paths}` 或 `null`，提供排除人物后的整体背景线稿。`tests/framing_sequence_flow.py` 验证显现、扫描、变焦的时间顺序，`tests/framing_camera_flow.py` 验证手机宽度下的实际倍率插值、取消操作、终点复核与 JPEG 裁切；`tests/mobile_flow.py` 还会断网回放从约 0.7 倍景别自动调整到约 1.43× 的过程。
